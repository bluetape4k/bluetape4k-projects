## L1: K3sContainer의 `kubeConfigYaml`은 Jackson YAML pretty-printer로 직렬화됨

### 문제
`yaml.contains("server: https://")` assertion이 실패했다. 실제 YAML은 Jackson이 URL 값을 따옴표로 감싸서 `server: "https://..."` 형태로 출력한다.

### 교훈
testcontainers K3sContainer는 kubeconfig를 Jackson YAML `writerWithDefaultPrettyPrinter()`로 재직렬화한다. 문자열 비교 시 `"https://"` 전체를 포함하는 형태로 검사하거나 포트 번호만 확인한다.

## L2: `@Tag("k8s")` 태그만으로는 CI 실행 차단 불충분

### 문제
`@Tag("k8s")`는 선언적 metadata일 뿐이고, Gradle `useJUnitPlatform { excludeTags("k8s") }`가 없으면 일반 CI에서도 K3s test가 실행된다. GitHub Actions `ubuntu-latest`는 비권한 환경이므로 K3s 시작이 실패한다.

### 교훈
K8s/Docker privileged test는 반드시 다음을 따른다.
1. `build.gradle.kts` `tasks.test { useJUnitPlatform { excludeTags("k8s") } }` 추가
2. 별도 `k8sTest` task로 privileged runner에서만 실행한다.

## L3: `kubernetesClient()` 반환 객체 자동 정리

### 결정
`kubernetesClient()`에서 생성한 `KubernetesClient`를 `ShutdownQueue.register(it)`로 등록한다. 호출자가 `.use { }` 없이도 JVM 종료 시 자동 정리된다.

---

## L4: reuse=true 컨테이너의 리소스 충돌

### 문제
`create namespace/lease → assert → delete` sequence에서 중간에 test가 실패하면 resource가 남아 다음 실행에서 `AlreadyExistsException`이 발생한다.

### 교훈
Singleton container를 재사용할 때 각 test는 `try/finally`로 cleanup을 보장하거나 `@AfterEach`에서 `runCatching { }` pattern으로 resource를 제거한다.
