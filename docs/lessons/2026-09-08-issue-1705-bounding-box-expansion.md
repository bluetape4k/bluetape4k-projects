# 범위의 양 끝 확장은 독립적으로 검증한다

## 원인과 결정

[#1705](https://github.com/bluetape4k/bluetape4k-projects/issues/1705)의 `BoundingBox.expandToInclude(other)`는 위도 하한과 상한 갱신을 `if/else if`로 연결했다. 현재 범위가 10~20이고 상대 범위가 0~30이면 남쪽만 0으로 넓어지고 북쪽은 20에 머문다.

한 점은 현재 범위의 양쪽 바깥에 동시에 있을 수 없지만 다른 범위는 양쪽을 모두 포함할 수 있다. 따라서 상자를 합칠 때의 하한과 상한 비교를 독립적인 `if`로 분리한다. 한 점을 추가하는 overload와 경도 확장 알고리즘은 그대로 유지한다.

## 검증과 재발 방지

`BoundingBoxExtensionsTest`에 일반 경도와 날짜변경선 교차 사례를 추가했다. 수정 전 두 테스트가 북쪽 경계 30 대신 20을 반환해 실패했다. 각 테스트는 남북 경계뿐 아니라 양 끝점 포함, 기존 경도, 자오선 교차 상태도 확인한다. 최종 geo 전체 테스트와 정적 분석 결과는 연결 PR에 기록한다.

향후 범위 합집합을 변경할 때는 하한만 확장, 상한만 확장, 양쪽 동시 확장, 기존 범위 내부 사례를 구분한다. 한 점에 성립하는 상호 배타적인 조건을 범위 연산에 그대로 적용하지 않는다.
