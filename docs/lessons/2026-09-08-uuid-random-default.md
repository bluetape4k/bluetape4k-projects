# UUID 생성기의 기본 난수원을 시간 시드로 만들지 않는다

관련 이슈: https://github.com/bluetape4k/bluetape4k-projects/issues/1698

## 실패한 가정과 근거

기본 생성기 10000개에서 첫 UUID의 고유 값이 3개와 4개에 불과했다. 같은 밀리초의 시드가 난수열을 반복했다.

## 결정

Uuid.random과 이전 RandomUuidGenerator의 기본값을 SecureRandom으로 변경한다. 명시적으로 주입한 Random의 결정론적 계약은 유지한다.

## 재발 방지

한 생성기의 반복 호출뿐 아니라 여러 기본 생성기의 첫 결과를 검사한다. UUID 버전과 명시적 동일 시드 결과도 함께 검증한다.

## 검증

이 PR의 회귀 테스트에서 수정 전 동작 실패를 확인했다. 수정 후 테스트와 관련 모듈 검증 결과는 PR의 `DoD Status`에 기록한다.

## 검증의 한계

고유성 테스트는 확률적 검증이며 느린 환경에서 이전 시간 시드 구현이 항상 실패한다고 보장하지 않는다. 변경 전 실측 RED 결과를 별도 보존하고, 난수원 생성 코드와 명시적 시드 계약을 함께 검토한다. 기본 생성기마다 SecureRandom을 생성하는 비용은 측정하지 않았으므로 처리량 개선으로 주장하지 않는다.
