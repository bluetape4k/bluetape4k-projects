# PR #1889: Actions 업데이트와 catalog-governance 계약을 함께 유지한다

## 맥락

PR [#1889](https://github.com/bluetape4k/bluetape4k-projects/pull/1889)은
`actions/setup-java`와 `ruby/setup-ruby` 업데이트를 제안했지만, 현재
`develop`의 catalog-governance 검증기는 Dependabot Core checkout에 사용한
기존 `ruby/setup-ruby` SHA만 허용하고 있었다. 그 결과 업데이트 자체와
workflow 계약 검증이 서로 다른 상태를 요구했다.

## 결정

- `actions/setup-java`의 기존 tag 사용 위치는 `v6.2.0`으로 갱신한다.
- commit SHA로 고정한 `setup-java` 위치는 v6.2.0의
  `77dd5b2ce225ea11469928ac317850245a74ae78`로 갱신한다.
- catalog-governance의 `ruby/setup-ruby`는 PR이 제공한
  `b3aaceaef7e0ee231b499e7b5f49c03fc1d32199`를 사용하고, 검증기와 회귀
  테스트의 허용값도 같은 SHA로 맞춘다.
- `bundler-cache: false`와 runner-temp `BUNDLE_PATH` 계약은 그대로 유지해
  공유 캐시 쓰기를 허용하지 않는다.

## 검증

- RED: 새 Ruby pin을 검증기에서 요구하는 회귀 테스트가 기존 SHA 때문에
  실패했다.
- GREEN: workflow와 검증기 pin을 갱신한 뒤 동일 회귀 테스트와 전체
  catalog-workflow 검증을 다시 실행한다.
- hosted PR exact-head에서는 Central Catalog Governance와 transient
  gitleaks 재실행 결과를 별도로 확인한다. 기존 PR head의 실패는 새 head의
  성공을 증명하지 않는다.

## 다음 변경자를 위한 guard

Dependabot Actions 업데이트 때 workflow의 tag/SHA 사용 위치, catalog-governance
검증기 허용값, 회귀 테스트를 한 변경으로 갱신한다. action pin을 바꾸더라도
Bundler 공유 캐시와 exact-head checkout 계약은 약화하지 않는다.
