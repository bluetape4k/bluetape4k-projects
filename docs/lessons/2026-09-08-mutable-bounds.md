# 변경 가능한 좌표와 파생 상태를 분리하지 않는다

관련 이슈: https://github.com/bluetape4k/bluetape4k-projects/issues/1696

## 실패한 가정과 근거

공개 setter 변경 뒤 저장된 자오선 교차 플래그가 이전 좌표를 가리켰고 생성자/copy는 팩터리 검증을 우회했다.

## 결정

교차 여부는 현재 좌표로 계산하고 생성자에서 검증한다. 공개 setter와 data class 계약을 유지하며 공간 연산 진입 시 직접 변경한 좌표도 검증한다. 기존 직렬화 UID를 실측해 고정했다.

## 재발 방지

팩터리뿐 아니라 생성자, copy, 직접 변경, 직렬화를 각각 검증한다. setter 대입 순간의 검증과 소비 시점 검증을 같은 계약으로 설명하지 않는다.
