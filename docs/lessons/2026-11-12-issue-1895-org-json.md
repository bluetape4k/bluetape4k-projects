# Issue #1895 `org.json` 의존성 수렴 교훈

## 맥락

2026-11-12 기준 `origin/develop`의 정확한 HEAD는
`619eb71f89259f943f64fb995d7f16b7d2608be6`이다. 수정 전
Dependency Submission 산출물에는 다음 경로가 남아 있었다.

```text
com.falkordb:jfalkordb:0.8.0
└── redis.clients:jedis:7.5.0
    └── org.json:json:20251224
```

Dependabot alert `#279`는 `org.json:json`의 CVE-2026-59171
(GHSA-ghc9-756g-vrcv)을 보고했고, 첫 패치 버전은 `20260719`이다. 수정 전
Dependency Submission run `43109699702`는 성공했지만 SBOM에는 위 요청 경로가
그대로 남았다. 이전 실패 run `43057479716`에는 다음 오류가 기록되어 있었다.

```text
Job dependencies not found in the dependency snapshot: org.json:json
```

## 원인

`testing/testcontainers/build.gradle.kts`의 `compileOnly(bt4k.jfalkordb)`가
Jedis 7.5.0을 끌어오고, Jedis의 메타데이터가 취약한 `org.json:json` 버전을
전이 의존성으로 요청했다. 중앙 catalog에는 아직 `org-json` alias가 없어서
catalog 값만 바꾸는 방식으로는 이 저장소의 요청 edge를 고칠 수 없었다.

선택된 버전만 패치 버전으로 올리면 hosted Dependency Submission의 요청
edge에 취약 좌표가 남을 수 있다. 따라서 요청 edge와 선택 edge를 모두
검사해야 한다.

## 결정

- `redis.clients:jedis`의 모든 variant에서 기존 `org.json:json` dependency를
  제거하고 첫 패치 버전 `20260719`을 추가한다.
- buildscript classpath와 프로젝트 configuration에 같은 metadata rule을
  적용해 published graph와 Dependency Submission graph의 경계를 맞춘다.
- 대표 프로젝트의 `compileClasspath`, `runtimeClasspath`, test classpath,
  published configuration, buildscript classpath를 검사하는
  `issue1895DependencyGraphCheck`를 추가한다.
- 그래프 가드는 `dependency.requested`와
  `ResolvedDependencyResult.selected.moduleVersion`을 모두 검사한다.
- 중앙 catalog에 `org-json` alias가 추가되면 이 저장소의 임시 override를
  shared security train으로 교체한다.

## 남은 검증과 후속 조치

이번 작업은 PR/merge/push 권한 범위 밖이므로 새 exact-head hosted CI,
Dependency Submission artifact read-back, Dependabot alert 종료 여부는 아직
확인하지 않았다. 따라서 #279가 해소되었다고 주장하지 않는다.

다음 hosted 실행에서는 다음을 다시 확인해야 한다.

1. 수정 branch의 exact HEAD로 Dependency Submission이 성공하는가.
2. 업로드된 SBOM에 `org.json:json`의 요청·선택 경로가 모두 `20260719`
   이상으로 기록되는가.
3. Dependabot alert `#279`가 닫혔는가.
4. 별도 이슈 #1896의 `KafkaStreamsTests` lifecycle/readiness 실패를
   독립적인 bugfix workflow로 처리하는가.

이 교훈의 재발 방지 장치는 `issue1895DependencyGraphCheck`이며, 중앙
catalog alias가 생기면 metadata override와 함께 갱신해야 한다.
