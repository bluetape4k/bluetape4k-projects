# Issue #1895 `org.json` 의존성 수렴 교훈

## 맥락

2026-11-12 기준 `origin/develop`의 정확한 HEAD는
`779d4659275b0670cac016ef2779d18caec1cda5`이다. 수정 전
Dependency Submission 산출물에는 다음 경로가 남아 있었다.

```text
com.falkordb:jfalkordb:0.8.0
└── redis.clients:jedis:7.5.0
    └── org.json:json:20251224
```

Dependabot alert `#279`는 `org.json:json`의 CVE-2026-59171
(GHSA-ghc9-756g-vrcv)을 보고했고, 첫 패치 버전은 `20260719`이다. 수정 전
Dependency Submission run `43109699702`는 성공했지만 SBOM에는 위 요청 경로가
그대로 남았다. 이전 실패 run `43057479716`에는 다음 오류가 기록되어 있었다.

```text
Job dependencies not found in the dependency snapshot: org.json:json
```

## 원인

`testing/testcontainers/build.gradle.kts`의 `compileOnly(bt4k.jfalkordb)`가
Jedis 7.5.0을 끌어오고, Jedis의 메타데이터가 취약한 `org.json:json` 버전을
전이 의존성으로 요청했다. 중앙 catalog에는 아직 `org-json` alias가 없어서
catalog 값만 바꾸는 방식으로는 이 저장소의 요청 edge를 고칠 수 없었다.

선택된 버전만 패치 버전으로 올리면 hosted Dependency Submission의 요청
edge에 취약 좌표가 남을 수 있다. 따라서 요청 edge와 선택 edge를 모두
검사해야 한다.

## 결정

- `redis.clients:jedis`의 모든 variant에서 기존 `org.json:json` dependency를
  제거하고 첫 패치 버전 `20260719`을 추가한다.
- buildscript classpath와 프로젝트 configuration에 같은 metadata rule을
  적용해 published graph와 Dependency Submission graph의 경계를 맞춘다.
- 대표 프로젝트의 `compileClasspath`, `runtimeClasspath`, test classpath,
  published configuration, buildscript classpath를 검사하는
  `issue1895DependencyGraphCheck`를 추가한다.
- 그래프 가드는 `dependency.requested`와
  `ResolvedDependencyResult.selected.moduleVersion`을 모두 검사한다.
- 동적·versionless `org.json` 요청은 fail-closed로 판정하고, non-resolvable
  consumable configuration의 declared edge도 published graph로 검사한다.
- 중앙 catalog에 `org-json` alias가 추가되면 이 저장소의 임시 override를
  shared security train으로 교체한다.

## 남은 검증과 후속 조치

수정 branch는 최신 `origin/develop`을 포함하고 hosted exact-head CI도
성공했다. 다만 Dependency Submission workflow는 `develop` push에서만
실행되므로 PR 단계에서는 수정 head의 SBOM과 Dependabot alert read-back을
완료할 수 없다. 따라서 #279가 해소되었다고 아직 주장하지 않는다.

`develop` delivery 이후에는 다음을 다시 확인해야 한다.

1. 수정 branch의 exact HEAD로 Dependency Submission이 성공하는가.
2. 업로드된 SBOM에 `org.json:json`의 요청·선택 경로가 모두 `20260719`
   이상으로 기록되는가.
3. Dependabot alert `#279`가 닫혔는가.
4. 별도 이슈 #1896의 `KafkaStreamsTests` lifecycle/readiness 수정은 PR
   #1898에서 exact-head CI를 통과했는가.

이 교훈의 재발 방지 장치는 `issue1895DependencyGraphCheck`이며, 중앙
catalog alias가 생기면 metadata override와 함께 갱신해야 한다.

## 후속 hosted SBOM read-back — 전체 producer edge 수렴

초기 Jedis 수정이 병합된 뒤 `develop` exact head
`b70f768470f8049b6fe766d34413429a5e0c563a`의 Dependency Submission run
`43167486905`를 다시 읽었다. Jedis 경로는 `20260719`로 수렴했지만 SBOM에는
다음 두 요청 edge가 남아 있었다.

```text
tools.jackson.datatype:jackson-datatype-json-org:3.2.4
└── org.json:json:20250107

io.swagger.codegen.v3:swagger-codegen:3.0.82
└── io.swagger:swagger-codegen:2.4.46
    └── org.json:json:20231013
```

Dependabot alert `#279`는 여전히 `open`이었고, advisory의 첫 패치 버전은
`20260719`였다. 원인은 Jedis 단일 producer만 metadata rewrite 대상으로
등록하고, Ktor OpenAPI 경로를 대표 그래프에 포함하지 않아 로컬 guard가
hosted SBOM의 Jackson/Swagger 요청 edge를 놓친 것이었다.

후속 수정은 다음 네 producer를 동일한 metadata rule로 수렴하고, Issue
`#1895` 전용 대표 프로젝트에 `:bluetape4k-ktor-openapi`를 추가한다.

- `redis.clients:jedis`
- `tools.jackson.datatype:jackson-datatype-json-org`
- `io.swagger:swagger-codegen`
- `io.swagger.codegen.v3:swagger-codegen`

후속 로컬 검증은 다음과 같다.

| 검사 | 결과 |
|---|---|
| 후속 TDD RED/GREEN | producer 목록과 공통 rule 계약 테스트가 기존 코드에서 RED, 수정 후 GREEN |
| 저장소 계약 테스트 | `python3.13 -m unittest tests.test_catalog_workflows` — 150 tests, OK |
| 전체 Issue #1895 대표 그래프 | `./gradlew issue1895DependencyGraphCheck --no-configuration-cache --no-daemon` — `:bluetape4k-ktor-openapi` 포함, BUILD SUCCESSFUL |
| Ktor OpenAPI selected graph | `dependencyInsight`가 `org.json:json:20260719` 출력, `swagger-codegen` 경로 확인 |
| Testcontainers selected graph | `dependencyInsight`가 `org.json:json:20260719` 출력, Jedis 경로 확인 |
| 영향 모듈 컴파일 | `:bluetape4k-ktor-openapi:compileKotlin`, `:bluetape4k-testcontainers:compileKotlin` — BUILD SUCCESSFUL |

후속 PR 병합 전에는 hosted exact-head CI가 필요하고, 병합 후에는 Dependency
Submission exact-head, SBOM의 모든 `org.json:json` 관계, Dependabot alert
`#279` 종결을 다시 확인해야 한다. 이 read-back이 끝나기 전에는 취약점
수렴을 완료했다고 주장하지 않는다.
