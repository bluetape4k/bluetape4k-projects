# 위경도 검증과 원본 좌표 경계를 분리한다

관련 이슈: https://github.com/bluetape4k/bluetape4k-projects/issues/1697

## 실패한 가정과 근거

`BoundingBox`는 최소/최대 순서만 검사해 위도 범위 밖 값을 허용했다.
생성자에 위경도 검증만 추가하자 기존 Shapefile 임포트 테스트가 실패했다.
`loadShape`가 CRS 변환 전에 미터 단위 경계를 같은 타입으로 생성하기 때문이다.
추가한 직접 읽기 테스트도 Y값 `4518366.509981736`을 위도로 검사하면서 실패했다.

## 결정과 호환성

사용자가 공개 API 변경을 승인한 뒤 `ShapeBounds`로 원본 X/Y 경계를 분리했다.
`BoundingBox`는 기존 `requireInRange`를, `ShapeBounds`는 기존 `requireFinite`를
재사용하며 각 타입의 생성자와 `copy`에서 해당 좌표 계약을 검사한다.
새 외부 의존성이나 모듈은 추가하지 않았다.

Shapefile 헤더·레코드·경계 계산은 `ShapeBounds`를 사용한다. 필터링은 같은 좌표계를
전제로 하고 자동 변환하지 않는다. DB 임포트는 원래 CRS 변환을 유지한 뒤 WGS84 경계를 검증한다.
`ShapeHeader`와 `ShapeRecord`는 필드 타입이 바뀌므로 직렬화 버전을 2로 올렸다.
호출자 소스 수정, 재컴파일, 이전 직렬화 객체의 재생성이 필요하다.
README 두 언어에 축 이름 대응과 이행 예제를 기록했다.

## 검증과 놓친 점

투영좌표 직접 읽기의 RED와 수정 후 동기·비동기 읽기, 경계 계산·필터링,
생성자·copy·직렬화 테스트를 확인했다. 상세 명령과 전체 모듈 결과는 PR의
`DoD Status`에 기록한다. 최종 Science 전체 테스트 283개와 Detekt가 통과했다.
독립 설계 리뷰에서 단일 레코드만으로 합집합을 검증하지 못한 점을 지적받아
다중 레코드 합집합, 경계 포함·제외, 두 필터 overload의 동등성 테스트를 추가했다.
DB 테스트의 파일 생성 코드는 직접 읽기 테스트와 공유해
동일한 EPSG:3857 자료로 읽기와 임포트를 검증한다.
초기 테스트 helper 추출 때 필요한 `File` import를 제거해 컴파일에 실패했고,
이를 복원한 뒤 실제 입력 검증 실패를 RED 근거로 사용했다.

## 재발 방지

도메인 검증을 강화할 때 생성자 호출자를 따라가 단위와 좌표계가 같은지 먼저 확인한다.
위경도 범위, NaN, 무한대, 극점, 날짜 변경선, 생성된 `copy` 경로와 투영좌표 읽기를 함께 검증한다.
science의 경도 순서 계약을 geo의 날짜 변경선 교차 계약과 혼동하지 않는다.
