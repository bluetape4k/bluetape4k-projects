## 검증 명령과 기대 결과

```bash
./gradlew :bluetape4k-testcontainers:compileTestKotlin
./gradlew :bluetape4k-testcontainers:test --tests '*OpenFgaServerTest' --no-parallel
./gradlew :bluetape4k-testcontainers:test --tests '*QdrantServerTest' --no-parallel
./gradlew :bluetape4k-testcontainers:test --tests '*PropertyExportingServerContractTest' --no-parallel
./gradlew :bluetape4k-openfga:test --no-parallel
./gradlew :bluetape4k-qdrant:test --no-parallel
./gradlew :bluetape4k-testcontainers:detekt :bluetape4k-openfga:detekt :bluetape4k-qdrant:detekt
./gradlew :bluetape4k-openfga:dependencyInsight --dependency testcontainers-openfga --configuration testRuntimeClasspath
./gradlew :bluetape4k-qdrant:dependencyInsight --dependency testcontainers-qdrant --configuration testRuntimeClasspath
python3 -m unittest discover -s scripts -p 'test*testcontainers*.py'
git diff --check
```

신규 클래스를 등록한 PropertyExportingServerContractTest에서 ClassNotFoundException RED를 먼저 관찰했고, 구현 후 같은 테스트 12개가 GREEN이었다. 컨테이너 모듈 검증은 순차 실행한다. image-gate manifest 검증과 선택 workload 실행을 추가해 startup/workload 증거를 확인한다. 기존 detekt 문제가 있으면 기준 head와 비교하고 신규 위반은 모두 수정한다.

## 위험과 복구

새 API는 additive이고 기존 infra 테스트만 fixture를 교체하므로 서비스 SDK 공개 API는 유지된다. 상위 클래스의 Java getter와 Kotlin property 충돌은 compile 단계에서 확인한다. 공식 컨테이너 compileOnly 의존성을 소비자가 빠뜨리면 NoClassDefFoundError가 발생하므로 소비자 컴파일·실행을 함께 검증한다. 실패 시 Server·dependency·fixture adoption 변경을 같은 단위로 되돌린다. 고정 포트 테스트는 Launcher 시작 전에 실행하거나 별도 테스트 JVM을 사용한다. 테스트 속성은 기존 값을 복원하고 공유 Launcher는 종료하지 않는다.

## 현재 상태

설계 및 계획 작성 완료. 단계 1~6 완료. 단계 7의 독립 리뷰와 lesson 완료, PR/새 head CI는 진행 중이다. 이번 작업은 기존 모듈 안의 Server 추가이므로 신규 Gradle 모듈·BOM artifact·Kover 모듈 등록은 N/A이며 이미지 게이트 등록은 필수이다.

소비자 의존성은 `testImplementation(libs.testcontainers.openfga)`와 `testImplementation(libs.testcontainers.qdrant)`이다. 공개 Java getter를 Kotlin 프로퍼티로 재선언하지 않는다. README에 Docker host binding과 무인증 테스트 전용 사용 범위를 명시한다. `actionlint .github/workflows/ci.yml .github/workflows/nightly-tests.yml`를 실행한다. image-gate 실행 옵션은 helper --help로 확인하여 두 family를 순차 검증한다.

실제 image-gate 선택은 legacy family에 platform 설정이 없어 `--scope family` 대신 `--scope changed --changed-path <Server.kt> --require-selection`을 사용했다. OpenFGA·Qdrant 각각 1/1 성공이며 전체 49개 release family를 실행한 것으로 확대 해석하지 않는다.
