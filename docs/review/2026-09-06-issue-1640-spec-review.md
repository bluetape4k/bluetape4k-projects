- 재검토 대상 v2 SHA256: `e8a2f375a003c0e63c6e7989bf8081cc6d51e931cdd314d039f66d7e86ab5dc2`.

- 성능과 안정성은 별도 native agent가 검토했다. 보안·운영·API·호출자 관점은 agent thread limit으로 생성에 실패하여 주 담당자가 직접 검토했다. 6개 독립 리뷰로 집계하지 않는다.

## 지적과 처리

| 심각도 | 지적 | v2 처리 및 위치 |
|---|---|---|
| P1 | 시작·작업·종료에 구체적인 시간 제한이 없음 | 명세 71–73행에 30초·5초·10초·전체 60초, 격리 검증 프로세스 10분 상한과 interrupt 한계 명시 |
| P1 | 순환 의존 fixture와 실패 원인 판정이 불명확함 | 45–51행에 EMF 생성자 의존, 구체 executor 반환 타입, 정상 자동 구성 순서와 예외 원인 분류 명시 |
| P2 | JPA matrix 비용과 동시 실행 범위가 불명확함 | 37–39행에 8개 context, 순차 실행, 저장·조회 1개 사례, 사례별 작업 1개로 제한 |
| P2 | 일반 executor 인터페이스에 종료 거부 계약을 적용할 위험 | 73–75행에 구체 executor 타입과 Hikari pool 종료 판정 명시 |
| P2 | 구버전 정렬 실패와 upstream 회귀 재현을 혼동할 위험 | 112–114행에서 4.0.3 catalog 불일치와 4.1.0 순환 의존 RED를 구분 |

안정성 재검토는 v2의 P0/P1 잔여 없음으로 회신했다. 성능 재검토는 v2에서 전체 모듈 실행의 프로세스 상한 누락을 P1으로 지적했다. v3는 71–75행과 AC-05에서 시간 assertion과 interrupt의 한계를 구분하고, 단독 10분·각 전체 모듈 30분·CI 유한 timeout 및 소유한 자식 JVM의 종료를 명시했다. 위 표의 행 번호는 v2 기준이다.

## 남은 검증과 위험

- 동기 context 시작·종료는 interrupt를 무시할 수 있다. 문서의 시간 경계가 강제 종료를 보장하지 않으며 격리 검증 프로세스 제한도 구현 단계에서 확인해야 한다.
- 4.1.0/4.1.1 동일 fixture 비교는 아직 실행하지 않았다. 이를 수행하지 않으면 upstream 회귀를 직접 재현했다고 보고하지 않는다.
- 기존 controller 테스트 3개 통과와 dependencyInsight는 준비 단계 증거다. 신규 fixture, 전체 모듈, 정적 검사 및 exact-head CI는 대기다.
- 외부 조사 자료의 wiki 보존·색인, 구현 계획, lesson, PR은 후속 단계다.
- 실패한 review lane의 runtime 대체 완료 연결은 전체 워크플로 종료 전에 정리해야 한다. 문서 리뷰 판정과 runtime 전체 완료를 혼동하지 않는다.
